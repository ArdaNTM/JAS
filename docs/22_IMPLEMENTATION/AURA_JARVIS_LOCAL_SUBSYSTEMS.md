# Local JARVIS subsystems — candidate acceptance

STT shares one faster-whisper recognizer between HTTP and full-duplex fallback (Sherpa remains an independent optional backend). PyAV decodes in memory before inference. With auto device selection, CUDA load/inference failures switch the shared process cache to CPU INT8; invalid audio does not trigger a device fallback. AURA_STT_CPU_MODEL defaults to small; explicitly configured model and offline model paths are preserved.

Local Owner and HTTP bearer configuration are prerequisites for these additional providers. All tool execution crosses the existing MCP Gateway. No feature completion or physical acceptance is claimed here.

- AURA_MORNING_BRIEFING_ENABLED=1: GET /api/jarvis/briefing; HUD button and exact voice commands "günün planı", "günaydın", "morning briefing". Bounded read-only task, dependency, workflow and checkpoint projections. Text is untrusted data.
- AURA_BACKGROUND_THINKING_ENABLED=1: existing idle daemon invokes semantic consolidation after at least 300 seconds without activity. AURA_OLLAMA_BASE_URL defaults to http://127.0.0.1:11434; AURA_SEMANTIC_CONSOLIDATION_MODEL defaults to qwen3. Local inference only; source-linked, deduplicated untrusted summaries retain original episodes. Task erasure removes derived summaries.
- AURA_IOT_ENABLED=1: configure AURA_IOT_PROFILES_JSON as an array of device_id and sensor_key_hex objects (independent 32-byte sensor key per device), AURA_IOT_NONCE_DB as an existing-parent absolute database path outside checkout, and AURA_IOT_MQTT_PORT, AURA_IOT_MQTT_USERNAME, AURA_IOT_MQTT_PASSWORD. Broker is loopback only; authenticated LAN bridging is separately provisioned. Existing signed physical-device topic namespaces are used: aura/robots/<id>/control, aura/sensors/<id>/power. POST /api/jarvis/iot/<id>/command accepts action on/off/status, request_id, optional approval_id. Reuse identical request arguments after approval. Submission is not proof of actuation; status requires signed fresh sensor evidence. POST /api/jarvis/iot/ticket and WebSocket /api/jarvis/iot/events?ticket=... expose only scoped device events. Approval store required.
- AURA_FACE_VERIFICATION_ENABLED=1: optional separately installed OpenCV with YuNet and SFace ONNX models. Configure absolute local AURA_FACE_REFERENCE_PATH, AURA_FACE_DETECTOR_PATH, AURA_FACE_RECOGNIZER_PATH, and optional AURA_FACE_CAMERA_INDEX. POST /api/jarvis/face/verify requires existing approval. No image/features are returned or persisted by the verifier. Mismatch restricts new IoT actuation only; a match can clear that restriction but never grants authority. Camera/model unavailable preserves current restriction state. No liveness or anti-spoofing claim.

Live acceptance requires real Turkish audio with cold/warm timing, actual local Ollama, a provisioned signed MQTT device, and a consented camera/reference comparison. CI evidence is software regression evidence only. Existing F2.7 and Owner cryptographic checks remain unchanged.
